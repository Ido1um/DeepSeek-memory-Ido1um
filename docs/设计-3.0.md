# 设计：3.0 的分层与契约

这篇文档讲 3.0 的数据形状与几条硬规则。想直接接宿主，看 [集成指南](集成指南.md)。

## 1. 为什么分层

2.x 的问题不是「记不住」，而是三件事混在一起：

1. **窗口与记忆混在一起** —— 轮转时只能靠摘要，摘要又会丢原话的细节和语气。
2. **抽取与写入混在一起** —— 模型抽一条就立刻进事实库，错了只能事后作废。
3. **事实与展示混在一起** —— 卡是事实库的直接拼接，越写越长、越写越乱。

3.0 把这三件事拆开：窗口账本管「当时到底说了什么」，情境段管「这一段在聊什么」，事实库管「长期成立的是什么」，卡只是事实库的一个受预算约束的投影。

## 2. 数据布局

```
<dataDir>/
  raw/
    hot/<YYYY-MM-DD>.jsonl        最近 N 天的逐条对话
    archive/<YYYY-MM>/*.jsonl     更早的按月归档
  window/
    blocks/<sha1>.txt             窗口文本块（内容寻址，同一段只存一份）
    <sessionId>/meta.json         会话元信息（key、开始时间、轮转次数）
    <sessionId>/turns.jsonl       逐轮账本：用户原话/助手发言/想法/块顺序
  episodes/
    <YYYY-MM>.jsonl               情境段（按 id 幂等 upsert）
  state/
    longterm.jsonl                事实事件流（只追加）
    facts-invalidated.json        作废墓碑
    topics.jsonl                  主题表（可选；没有就回退扁平卡）
    candidates.jsonl              宽进候选（pending/merged/rejected）
    feels.jsonl                   跨轮的情绪账（v10）
    extract-shadow.jsonl          模型抽取影子
    memory.json                   运行时状态（上次日终、注入标记等）
  logs/
    token-usage.jsonl             宿主侧 token 用量
    memory-usage.jsonl            记忆侧模型调用用量
    scoring.log                   打分/写入门/抽取日志
  profile.md                      事实卡（投影产物）
  profile-tone.md                 语气备忘（v10 投影产物）
  v10.json                        v10 开关（放数据目录，按 mtime 热读）
```

**只追加、不物理删**：事实是事件流（`fact / mention / tier / manual / invalidate / update / merge`），折叠出当前状态。作废是墓碑 + 审计，不是删行。

## 3. 窗口账本

一轮的生命周期：

```
beginTurn({ key, sessionId, prompt, text })
   ├─ 解析 prompt 里的【本次消息快照】，取出用户原话（ownerTextOf）
   ├─ 把拼好的窗口文本按块切开，内容寻址写 window/blocks/
   └─ 落一条草稿（turn 号在 finish 时才定）
…宿主发消息…
stripFeels(reply)        剥掉 [[feel]]…[[/feel]]，想法不发给对方
finishTurn({ key, sessionId, reply, spoken })
   ├─ 写 turns.jsonl：userRaw / blocks / spoken / feels
   └─ 清草稿
```

几条硬规则：

- **用户原话必须来自消息本体**。`ownerTextOf` 只从【本次消息快照】里取 `isOwner && !isSelf` 的最后一条，取不到就返回空——绝不把整段 prompt（里面可能有系统提示和记忆注入）当成用户原话。
- **想法只留账本**。`[[feel:xxx]]…[[/feel]]` 在发送前剥离，账本里保留（`includeReply` 时交接会带，但已发出去的文字会去重）。
- **块去重**：同一段文本（sha1 相同）只存一份，多轮复用。
- **草稿可回收**：宿主崩了留下的草稿，按超时清扫，不污染账本。

## 4. 轮转契约

```
pressure = 真实 token / 上下文窗口
pressure ≥ 0.7   → 允许自动轮转（tick 判定 due）或手动轮转
pressure < 0.7   → 只有 rotate(force, approved=true) 才放行
```

- 上下文窗口来源：模型元数据 > 已观测最大值 × 1.15 > 配置值。
- 冷却时间与最小轮转 token 一起挡掉抖动。
- 宿主侧的重置端点必须带 `{"approveRotation": true}`，否则在未达阈值时返回 409。

轮转后首屏（固定顺序，总量 `handoverMaxChars` 兜底）：

| 段 | 默认上限 | 来源 |
|---|---|---|
| 规则 | 600 | `rules.md` |
| 事实卡 | 1500 | 主题树投影 |
| 最近一天原话 | 2400（单轮 600） | 窗口账本 24h |
| 七天摘要 | 剩余预算 | 日终摘要 / 提取式回退 |

没有原话可带时（新会话、账本为空），退回提取式摘要，不编造。

## 5. 情境段

- 以 90 分钟为间隔切段；少于 4 轮并入上一段；单段最多 40 轮。
- 按 `id` 幂等 upsert：重跑不会产生重复段。
- 摘要字段：标题 / 场景 / 主题 / 想法；模型不可用时保留原样，不影响日终。
- 情境段不进注入，只服务检索与主题归并。

## 6. 长期事实与写入门

事实的最小形状：

```json
{ "id": "...", "kind": "hard|pref|note|event|task", "tier": "hard|long|general|temp",
  "about": "owner|bot|other", "topicId": "...", "slot": "...", "value": "...",
  "quote": "原文逐字子串", "confidence": 0.8, "dueAt": 0 }
```

写入门三档：

| 档 | 触发 | 结果 |
|---|---|---|
| `pass` | 明确、可引用、非转瞬 | 直接写事实 |
| `mark` | 不确定 / 转瞬 / 助手偏好 / 信息太薄 | 写候选或影子，带 `conf` 与提示 |
| `block` | 引用别人的话、元讨论（记忆/注入/测试/脚本/bug…） | 丢弃，记原因 |

`gateMode: strict` 是默认；`broad` 需要对低置信做影子观察，别一上来就放开。

## 7. 候选池与日终归并

宽进候选（模型抽取通过项、低置信项）先写 `state/candidates.jsonl`，`status=pending`：

- 不进卡、不进检索、不参与打分；
- 日终 merge 阶段裁决（合并 / 升级为事实 / 拒绝）；
- 同值换说法按 `about|class|value` 合并成一次提及，避免重复。

这样「抽错」的代价只是候选池里多一行，而不是卡上多一条错事实。

## 8. 主题树与槽位

- 主题表 `state/topics.jsonl`：根主题 + 子主题 + 别名。
- 每个事实挂 `topicId` 与 `slot`（24 个槽位：身份、偏好、设备、学业、日程…）。
- 出卡：根主题分组、子主题两格缩进、同槽留最新、预算超了整块丢并注明「（其余 N 条已省略）」。
- 没有主题表或 `profile.tree=false` 时回退旧的扁平投影。

## 9. 事实卡清洗

投影前先做确定性清洗（只改投影，不改真源）：

1. 未闭合括号截断修复；
2. 记忆系统技术噪声不进卡（记忆方案/注入/轮转/热备/脱敏）；
3. 叙事槽位少于 4 字且无编号的残句丢掉，名词槽位保留短词；
4. 型号归一（拉丁数字串去空格连字符，共享 ≥2 个型号视为同一条）；
5. 跨槽位去重（gear/game/edition 为权威）；
6. 单值槽位选最完整一条而非最新；
7. 多值封顶（pref/intel/note 3 条，event/plan/gear 2 条）；
8. 事件按有无日期 + 长度 + 档位排序；
9. 主体纠偏（身份/偏好槽位按句首主语，并列主语不挪）。

## 10. 分层检索

```
近 7 天情境段  →  近 7 天原话  →  近 30 天情境段
```

- 查询切中文二元组；切不出来（「鱼」「嗯」）回退 substring，避免 0 命中。
- 打分看词命中、时间衰减、情境与事实的相关度；注入有字数上限，按分数截断。
- 检索只读，不改库。

## 11. v10 记忆属性

每条事实可派生：细节 D、情绪 E、可信度 Q、碎片、干扰、激活值 A。

- 默认 `emit: false`：注入文本与排序逐字节不变，只记账，方便先观察。
- 打开后，检索段会按 Q 用三档措辞（记得清清楚楚 / 记得个大概 / 只剩零碎印象）。
- 语气备忘写 `profile-tone.md`，不进事实卡。

## 12. 用量与存储

- 宿主侧 token：`logs/token-usage.jsonl`（轮转判据）。
- 记忆侧模型调用：`logs/memory-usage.jsonl`，按 caller 区分（handover/profile/extract/episode/entry），工作台「消费账单」按分时价格聚合。
- 存储上限 `storage.maxDataMb`（默认 200）与最小剩余磁盘 `minFreeGb`（默认 10）；超了先归档旧月份，不动热数据。

## 13. 不变量

1. 不物理删事实；作废有墓碑与审计。
2. 用户原话只能来自消息本体，不能来自 prompt 拼接结果。
3. 想法（feel）不发给对方。
4. 未达 70% 上下文阈值的轮转必须有人批准。
5. 卡与检索都是有预算的投影，超预算整块丢弃并注明，不截半句。
6. 任何「模型产出」在通过硬规则与写入门之前，都只是候选。
