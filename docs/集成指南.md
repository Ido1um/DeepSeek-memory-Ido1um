# 集成指南

这篇讲怎么把记忆引擎接到一个宿主（QQ 桥接、桌面端、CLI、自己的聊天服务都行）。引擎不知道「消息怎么发」，宿主不该知道「事实怎么抽」。

## 1. 两种接法

| 接法 | 适合 | 说明 |
|---|---|---|
| **库模式**（推荐） | 宿主是 Node 进程 | `import { createMemoryEngine } from 'deepseek-memory-ido1um'`，引擎跑在同一进程里 |
| **MCP 模式** | 宿主只想要「查历史」工具 | 跑 `src/mcp-server.mjs`，宿主通过 MCP 调 `qq_memory_search` 等 |

库模式下宿主负责三件事：把消息交给引擎、把引擎返回的文本拼进 prompt、在合适的时候开新会话。

## 2. 最小接入

```js
import { createMemoryEngine } from 'deepseek-memory-ido1um';
import * as window from 'deepseek-memory-ido1um/window';

const engine = createMemoryEngine({
  getConfig: () => config,     // 返回 { memory: {...} } 或直接返回 memory 段
  host: {
    log: (msg) => console.log('[memory]', msg),
    listSessions: () => [...sessions.keys()],
    getSessionId: (key) => sessions.get(key) || '',
    retireSession: (key) => { sessions.delete(key); return true; },
    isBusy: (key) => busy.has(key),
    isDshReady: () => true,
    afterRotate: (key, info) => { /* 清宿主缓存 */ },
    getOwnerKey: () => 'private:10001',
    // 可选：真实上下文压力，给了就是权威值
    pressureTokens: (sid) => ({ tokens, window })
  }
});

engine.startMaintenance();   // 日终维护 + 轮转检查
```

## 3. 一轮的完整时序

```js
// ① 入站：先让引擎记录这条用户消息（打分/候选）
engine.onInbound(key, userText, { ts: Date.now() });

// ② 拼注入：引擎只返回文本，不负责送达
const composed = engine.composePrompt(key, sessionId, promptText);
// composed.text 已含规则/事实卡/交接/检索 + 【当前对话】

// ③ 窗口账本：把「实际要发出去的完整窗口」和「用户原话」记成草稿
window.beginTurn({
  key, sessionId,
  userRaw: userText,
  windowText: composed.text,
  blocks: window.splitWindowBlocks(composed.text),
});

// ④ 宿主发送，拿到回复
const reply = await sendToModel(composed.text);

// ⑤ 剥离想法后再发给对方
const { text: visible } = window.stripFeels(reply);
window.noteSpoken({ key, sessionId, tool: 'send_message', text: visible });

// ⑥ 落账本：这轮用户说了什么、助手发了什么、想法是什么
window.finishTurn({ dir: engine.dataDir(), key, sessionId, reply });

// ⑦ 确认注入已消费（只注入一次的关键）
engine.commitInjections(key, sessionId, composed);
```

顺序上的两个坑：

- `commitInjections` 必须在**送达成功之后**调用。提前调用会让交接/事实卡被标成已消费，模型却没看到。
- `beginTurn` 要拿**拼好的完整文本**（`windowText`），不是用户那一句；账本要能逐字重建当轮窗口。

## 4. 窗口账本的接口

| 函数 | 作用 |
|---|---|
| `beginTurn({ key, sessionId, userRaw, windowText, blocks })` | 开一轮草稿：记录用户原话与拼好的完整窗口（内存态，不落盘） |
| `splitWindowBlocks(text)` | 把完整窗口切成「规则/事实卡/交接/检索/对话」几块，供账本按块存 |
| `finishTurn({ dir, key, sessionId, reply })` | 落 `turns.jsonl`：userRaw / blocks / spoken / feels |
| `stripFeels(text)` | 去掉 `[[feel]]…[[/feel]]`，返回 `{ text, feels }` |
| `extractFeels(text)` | 只取想法数组（`[{ text }]`） |
| `noteSpoken({ key, sessionId, tool, text })` | 记录「真正发出去的话」（多气泡/工具发送时用） |
| `getDraft(sessionId)` / `dropTurn(sessionId)` | 草稿查看 / 丢弃 |
| `sweepDrafts({ dir, maxAgeMs })` | 清扫超时草稿 |
| `formatRecentSlice(dir, sessionId, { hours, maxChars, perTurn })` | 生成交接用的「最近一天原话」 |
| `ownerTextOf(prompt)` | 从唤醒 prompt 的【本次消息快照】取用户原话 |
| `appendImportedTurns({...})` | 批量导入历史轮次（自己写回填工具时用） |

`dir` 是数据目录；不传时用 `QQ_MEMORY_DIR` / 配置里的 `memory.dir`。

## 5. 轮转

```js
const st = engine.rotationStatus(key, sessionId);
// st.due / st.tokens / st.window / st.threshold / st.ratio

// 达到阈值：可以直接转
await engine.rotate(key, { reason: 'pressure' });

// 没到阈值：必须人批准
await engine.rotate(key, { force: true, approved: true, reason: 'user-asked' });
```

宿主侧如果暴露 HTTP 端点，务必也做同样的闸门：

```js
if (!approved && !engine.rotationStatus(key, sid).due) return res.status(409).end();
```

轮转前引擎会生成交接文本（`generateRotationHandover`）；新会话没有现成交接时，`ensureFallbackHandover` 会从日志补一份，失败则回退提取式摘要。

## 6. 配置

配置来源优先级：`QQ_MEMORY_CONFIG` 指定的文件 > `loadConfig()` 读到的对象 > 代码默认值。

数据目录优先级：`QQ_MEMORY_DIR` > `memory.dir` > `~/.deepseek-memory/data`。

```json
{
  "ownerQQ": "10001",
  "memory": {
    "enabled": true,
    "dir": "",
    "windowDays": 7,
    "dailyAt": "23:00",
    "handoverMaxChars": 5000,
    "rotation": { "thresholdRatio": 0.7, "minRotateTokens": 20000, "cooldownMs": 600000 },
    "profile": { "maxChars": 1500, "tree": true },
    "scoring": { "mode": "shadow", "gateMode": "strict" },
    "extract": { "enabled": false, "modelWrite": false },
    "selfWrite": { "enabled": true, "maxPerDay": 5, "maxTotal": 300, "initialI": 0.7 },
    "media": { "enabled": true, "maxBytes": 8388608, "maxPerTurn": 6 },
    "claims": { "enabled": true },
    "schedule": { "enabled": true },
    "window": { "gapRepair": true }
  }
}
```

完整键见 `config.example.json`；每个键的默认值在 `src/engine.mjs` 的 `DEFAULTS`。

### 模型凭据

日终摘要、情境摘要、模型抽取都需要模型：

| 变量 | 说明 |
|---|---|
| `DEEPSEEK_API_KEY` | API key（也可在配置里写 `apiKey`，或用 DSH 凭据） |
| `QQ_MEMORY_MODEL` | 模型名，默认 `deepseek-v4-flash` |
| `QQ_MEMORY_BASE_URL` | 兼容 Anthropic 的 base URL，默认 `https://api.deepseek.com/anthropic/v1` |

模型不可用时：日终照常归档与刷新事实卡（保留旧卡），摘要与抽取跳过，不阻塞主流程。

## 7. 定时任务

引擎自带 `startMaintenance()`：启动 5 秒后跑一次 `tick`，之后每 `checkIntervalMs`（默认 10 分钟）一次。`tick` 做两件事：

1. 到日终时间（`dailyAt`）且今天没跑过 → `runDailyMaintenance`：归档旧原文、刷新事实卡、打分归并、情境摘要、候选裁决、模型抽取、到期提醒。
2. 检查各会话的轮转判据，due 且不忙 → 轮转。

宿主如果自己有调度器，也可以只调 `runDailyMaintenance({ force })` 与 `tick()`，不要重复起 timer。

## 8. MCP server

```bash
DEEPSEEK_API_KEY=... node src/mcp-server.mjs
```

本包自带的 stdio server 提供两个只读工具：

| 工具 | 作用 |
|---|---|
| `qq_memory_search` | 查聊天原文（7 天热数据 + 归档） |
| `qq_memory_recall` | 查长期事实；默认 smart 路由（槽位/科目/主题/主体），带 `⟵ 窗口` 锚点与空结果诊断；课表问句先走结构化解析 |

3.1 的写侧能力以模块形式提供，由宿主接到自己的工具上（示例工具名见括号）：

| 能力 | 模块入口 | 说明 |
|---|---|---|
| 写一条事实 | `writeSelfFact()`（`src/self-write.mjs`） | 配额、去重、`author:'self'`、`I=0.7`；被抽取器跳过时记 `skip:self` |
| 改自写事实 | `reviseFact()`（`src/revise.mjs`） | 只允许 `author:'self'`；写 `ev:'revise'` + `logs/fact-history.jsonl` |
| 存/取图片 | `saveMediaBuffer()` / `readMedia()` / `toMediaRef()`（`src/media.mjs`） | 内容寻址；窗口只记 `mediaRefs` |
| 课表问答 | `scheduleAnswer()` / `coursesOn()`（`src/schedule.mjs`） | 周次 + 单双周过滤 |

宿主侧工具名若与上面不同，只要调用这些导出即可；本仓库不绑定具体宿主。

客户端配置示例（stdio）：

```json
{
  "mcpServers": {
    "deepseek-memory": {
      "command": "node",
      "args": ["/path/to/DeepSeek-memory-Ido1um/src/mcp-server.mjs"],
      "env": { "QQ_MEMORY_DIR": "/path/to/data" }
    }
  }
}
```

改完 `mcp-server.mjs` 必须重启客户端：stdio 子进程只在启动时注册工具。

## 9. 工作台

```bash
node workbench/server.mjs --port 7351
```

写操作要令牌（`WORKBENCH_TOKEN` 或 `workbench/.workbench-token`）。可用环境变量：

| 变量 | 作用 |
|---|---|
| `WORKBENCH_DIR` | 数据目录 |
| `WORKBENCH_DESIRED` | 目标配置文件（默认 `workbench/config.json`） |
| `WORKBENCH_BRIDGE_CFG` | 可选：宿主 config.json |
| `WORKBENCH_BRIDGE_LOG` | 可选：宿主日志 |
| `WORKBENCH_PRICE_MODULE` | 可选：价格表模块（`file:///...`） |
| `WORKBENCH_NO_OPEN=1` | 只起服务不开浏览器 |

## 10. 接入检查清单

- [ ] `engine.startMaintenance()` 起了，或宿主自己按时调 `tick()`
- [ ] `beginTurn` 传的是拼好的完整窗口文本
- [ ] `commitInjections` 在送达之后调用
- [ ] 发送前过 `stripFeels`
- [ ] 轮转端点有「未达 70% 要批准」的闸门
- [ ] `QQ_MEMORY_DIR` 指向持久化目录，且在备份范围内
- [ ] 模型凭据只放环境变量或宿主凭据库，不进仓库
