# 从 2.x 升级到 3.0

3.0 不破坏 2.x 的数据形状：原来的 `raw/`、`state/longterm.jsonl`、`state/memory.json` 都照读。新增的是窗口账本、情境段、主题表、候选池这些**旁路文件**。

## 1. 先备份

```bash
# 数据目录整个复制一份（3.0 会重写 profile.md 与 memory.json）
cp -r ~/.deepseek-memory/data ~/.deepseek-memory/data.bak-$(date +%Y%m%d)
```

Windows：

```powershell
Copy-Item -Recurse "$env:USERPROFILE\.deepseek-memory\data" "$env:USERPROFILE\.deepseek-memory\data.bak-20261104"
```

## 2. 升级代码

```bash
git fetch --tags
git checkout v3.0.0-beta.1
npm install        # 只有 MCP 需要
node --test        # 期望 355 通过
```

## 3. 冷启动检查

```bash
node scripts/memory-cli.mjs doctor
node scripts/memory-cli.mjs status
node scripts/memory-cli.mjs card
```

- `doctor` 看目录、坏行、权限、体积；
- `status` 看档位分布、日终时间、窗口与轮转阈值；
- `card` 看新投影出来的卡是否符合预期（这一步只读，不写库）。

## 4. 分阶段打开新能力

Beta 建议按这个顺序，每步观察一两天：

| 阶段 | 开关 | 观察点 |
|---|---|---|
| ① 先只记账 | `scoring.mode: "shadow"`、`extract.enabled: false` | 日志里有没有异常、候选池是否为空 |
| ② 窗口账本 | 宿主接上 `beginTurn/stripFeels/finishTurn` | `window/<sid>/turns.jsonl` 是否逐轮增长，原话是否正确 |
| ③ 情境段 | `episode.summarize: true` | `episodes/<月>.jsonl` 是否按天生成，摘要是否离谱 |
| ④ 主题树 | 生成 `state/topics.jsonl` | `card` 输出是否按主题分组、有没有残句 |
| ⑤ 写入门放开 | `scoring.gateMode: "broad"` + `gateShadow: true` | 候选池的通过率与重复率 |
| ⑥ 模型抽取 | `extract.enabled: true`、先 `modelWrite: false` | `state/extract-shadow.jsonl` 的影子质量 |

主题表迁移（可选，模型分类为主）：

```bash
node scripts/migrate-topics.mjs            # 模型分类
node scripts/migrate-topics.mjs --rules    # 纯规则，不调模型
node scripts/migrate-topics.mjs --repair   # 纠偏已知误挂
```

情境段补建（可选）：

```bash
node scripts/build-episodes.mjs --days 7           # 预览
node scripts/build-episodes.mjs --days 7 --write   # 落盘
```

## 5. 配置差异

2.x → 3.0 新增/改名的键：

| 键 | 变化 |
|---|---|
| `memory.handoverMaxChars` | 默认 3500 → **5000** |
| `memory.rotation.*` | 原来分散在轮转逻辑里，现在统一成 `rotation: { thresholdRatio, cooldownMs, minRotateTokens, contextWindowTokens }` |
| `memory.handover.recentSlice` | 新增：最近一天原话的时长/字数/单轮上限 |
| `memory.profile.tree` | 新增：有主题表时按树出卡（默认 true） |
| `memory.scoring.gateMode` / `gateShadow` | 新增：写入门档位与影子 |
| `memory.extract.*` | 新增：日终模型抽取（默认关） |
| `memory.episode.*` | 新增：情境摘要（默认开，模型不可用自动跳过） |
| `memory.retrieval.*` / `wander.*` | 新增：分层检索与主动翻旧账 |

旧的 `memory.profile.maxChars`、`windowDays`、`dailyAt`、`policy`、`reminders` 语义不变。

## 6. 回滚

```bash
git checkout v2.1.1        # 或你原来的版本
# 数据目录：把第 1 步的备份换回来
```

只回滚代码、不回滚数据也可以：2.x 不认识 `window/`、`episodes/`、`topics.jsonl`、`candidates.jsonl`，会直接忽略；但 `profile.md` 已被 3.0 重新投影过，2.x 会照用这份新卡。

## 7. 常见疑问

**Q：2.x 的事实会不会被 3.0 改坏？**
不会。3.0 对事实只追加事件（`update`/`invalidate`/`merge`），不改历史行；清洗只发生在投影层。

**Q：一定要接窗口账本吗？**
不接也能用：没有 `window/` 时轮转交接退回提取式摘要，检索只用原文日志。但「最近一天原话」和「当时的想法」就没有了。

**Q：可以不装主题表吗？**
可以。没有 `state/topics.jsonl` 时事实卡走旧的扁平投影。

**Q：为什么测试数从 2.x 的 200 多变成 355？**
3.0 新增了窗口、情境、主题、卡清洗、检索、写入门、候选池、用量等模块的用例。
