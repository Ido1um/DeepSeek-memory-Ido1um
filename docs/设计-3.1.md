# 设计：3.1 的六个新契约

3.0 把记忆拆成「窗口账本 → 情境段 → 事实 → 卡片」四层。3.1 不动分层，只补六个让记忆**可写、可查、可核对**的契约。所有改动都是追加式事件，3.0 的数据目录可以直接用。

总原则没变：**唯一真源是事件流**（`state/longterm.jsonl`、`window/<sid>/turns.jsonl`、`episodes/*.jsonl`），卡片、检索、工作台都是从真源算出来的投影；任何一步失败都不能写坏真源。

## 1. 自写事实（`src/self-write.mjs`）

**动机**：抽取器只能从「主人说的话」里提炼事实。她主动许下的承诺、自己发现的偏好、想留给以后的话，没有落点。

**形状**：一条普通事实，多三个字段。

```json
{ "ev": "fact", "id": "h-self-…", "sig": "t-bot|note|<hash>",
  "about": "assistant", "author": "self", "voice": "first",
  "topicId": "t-bot", "slot": "note", "kind": "note",
  "value": "我不喜欢吃西瓜", "text": "可选，≤400 字，检索时逐字给出",
  "I": 0.7, "saidAt": 1730000000000 }
```

**不变量**

1. `value` 2–60 字、`text` ≤400 字；同一 `topicId + slot + value` 只写一次（`sigFor()` 去重）。
2. 默认配额 5 条/天、300 条上限（`selfStats()` 统计），超限返回错误而不是静默丢弃。
3. `I` 初值 0.7，之后与同槽位事实走同一套衰减与提及加权——自写不享有额外权重。
4. 抽取器写库前调 `shouldSkipExtract()`：同 `topicId + slot` 已有自写单值时跳过，并用 `recordExtractSkip()` 把被跳过的候选写进 `state/staging.jsonl`（`reason:'skip:self'`），保证「不覆盖」可审计。
5. 自写事实可进卡、可检索，卡里保留第一人称原句，不加「她说」。

**回滚**：`memory.selfWrite.enabled=false`；已写事实保留（它们就是真源）。

## 2. 修订留痕（`src/revise.mjs`）

**契约**：`reviseFact(dir, id, patch, { by, role })`。

- 主人角色（`role:'owner'`）可改任意事实；助手只能改 `author:'self'` 或 `about:'bot'` 的事实。抽取器写的、关于主人的事实只能由主人改口，走抽取器的 `supersede`，不经过这里。
- 每次修订追加 `ev:'revise'`（`id`、`before`、`after`、`by`、`at`、`reason`、`revision`），并镜像到 `logs/fact-history.jsonl`。
- `readFactHistory(dir, id)` 返回完整修订链，工作台 `/api/history` 直接渲染。
- **回滚 = 再修订一次**，不是删除历史；`revision` 单调递增。

## 3. 问法路由（`src/route.mjs`）

**动机**：她问「我生日是什么时候」，逐字匹配命中 0 条——这是 3.0 线上检索长期为 0 的根因。

**契约**：`routeQuery(text)` 产出 `{ slots, topics, subjects, who, day, weekday, schedule, subjects }`，`scoring-runner.search({ match: 'smart' })` 消费它。

排序权重（从高到低）：

| 命中 | 加权 |
|---|---|
| 槽位（生日/器材/专业…） | +8000 |
| 科目（408/832/301/数一…） | +7000 |
| 主题 | +6000 |
| 词法（每个词，封顶 10 词） | ≤ +1200 |
| 主体（仅槽位/主题命中时） | +900 |
| 日期（今天/明天/周几） | +4000 |
| 课表 | +1500 |
| 已过期 | −3000 |
| 主体不符 | −4000 |
| 生日 who 不符 | −3000 |

**不变量**

1. 结构命中永远压过词法命中：词法封顶 1200，低于最小的结构权重。
2. 排序是**全序**（同分按 `I`、`saidAt`），不依赖数组顺序。
3. v10 的 `rankInInject` 改为「结构 rank 优先、激活值 tiebreak」；关掉 v10 时结果不变。

## 4. 召回格式（`src/recall-format.mjs`）

**契约**：`formatRecallBody(rows, { eps, dir })` 返回 `{ body, anchors }`。

- 每行末尾 `⟵ 窗口 MM-DD 轮 a–b（session 前 8 位）`：自写事实用自身 `src{kind:'window'}`；抽取事实用 `source.episodeId` 去 `episodes/*.jsonl` 反查 `sessionId / turnFrom / turnTo`。查不到就返回 `null`，**不硬编**。
- 自写事实标〔自己写的〕；有图的轮次附 `📎 有图（sha1 前 8 位）`。
- 空结果由 `emptyRecallText()` 输出四段：把它当成了什么（槽位/主题/主体）、相关但已过期（带日期）、只是词面相近、下一步怎么查（换说法 / 翻原文 / 展开窗口）。
- **不变量**：渲染只读，不写任何文件；同一行的事实内容逐字来自库，不改写、不总结。

## 5. 图片记忆（`src/media.mjs`）

**动机**：图片进上下文很贵；但「那天的照片」是记忆的一部分。

**契约**：内容寻址仓库。

```
media/YYYY-MM/<sha1>.<ext>
state/media.jsonl   { sha1, rel, ext, mime, bytes, kind, at, day, key, msgId, alt }
```

- `saveMediaBuffer()` 按 sha1 去重：同图重复发只补 `msgId/key/alt`，不重复占空间。
- 窗口账本只记 `mediaRefs:[{sha1,kind,mime,bytes,at,alt}]`，**图片字节不进账本、不进注入**。
- `readMedia(dir, sha1)` 取原字节；未知 sha1 返回 `null`（宿主回 404「这张图片没有留在记忆里」，不要编造画面）。
- 限额 `maxBytes` 8MB、`maxPerTurn` 6；超限只记日志、不阻断对话。

## 6. 课表（`src/schedule.mjs`）

**契约**：事实挂 `t-schedule` 主题、`slot:'course'`，带结构化字段。

```json
{ "course": { "name": "示例基础课", "day": 5, "start": "08:00", "end": "09:40",
              "parity": "all", "weekFrom": 1, "weekTo": 18,
              "location": "示例楼 A507", "semester": "2026秋" } }
```

- `state/calendar.json` 记学期起止、总周数、锚点（某天是第几周）；`weekOf()` / `parityOfWeek()` 由此推周次与单双周。
- `parseCourse()` 只解析「周几 + 时间/教室 + 课程名」的单条；拼句、跨句描述进 review，不硬拆。
- `coursesOn(dir, date)` 过滤：周几相等 + 周次在 `[weekFrom, weekTo]` + 单双周匹配 + 同学期。
- `scheduleAnswer()` 输出固定格式：`YYYY-MM-DD 周X · 第 N 周（双周）：- 课程｜时间 · 地点`；当天没课输出「今天没有课」而不是空串。
- 卡片用 `WEEK_LABEL` / `PARITY_LABEL` 结构化渲染，不再显示自由文本。

## 7. 窗口缺口回填（`src/gapfill.mjs`）

**问题**：宿主漏记入站消息时，窗口账本会缺轮，抽取就漏掉纠正和课表。

**契约**

1. 入站时 `noteInbound(key, msg)` 缓存原话（内存 30 分钟、每 key ≤60 条）；`beginTurn` 在 `ownerTextOf()` 取不到原话时用它兜底。
2. 日终（建段之前）`repairGapsForKey(key, { days: 2, write: true })`：读 `raw/`，与账本按 `msgId` / 正文 hash 反向核对，把连续的主人消息合成一轮补写，`fidelity:'reconciled'`、`source:'raw-gap'`、`reason:'raw-gap'`，日志 `logs/window-gap.log`。
3. 跨会话归属：时间距离最近者优先，平手归更晚的会话。
4. **不变量**：只补不缺的，不覆盖已存在的轮；补写行按 `at` 排序参与 `segmentTurns`，所以 `turn` 号可能大于后一行——排序一律按时间。
5. 开关 `memory.window.gapRepair`（默认开）；CLI `scripts/repair-window-gaps.mjs --days 3 --write` 可手动跑。

## 8. 纠正候选（`src/claims.mjs`）

**契约**：她说的话里如果是在纠正一个事实（含科目/专业代码、非元讨论、非寒暄），不直接写库，先进待确认队列。

- 写 `state/claims.jsonl`（`status:'pending'`，按归一化哈希去重，每日封顶 10）。
- 工作台确认 → 写一条 `author:'correction'` 事实；同 `topicId + slot`（同 `program`）已有 active 旧值时用 `supersede` 退掉，否则新增。驳回 → 留审计记录，不写库。
- **不变量**：确认前不影响卡片与检索；一次确认只退一条旧值（单值槽位语义），多值槽位按 `program` 等维度分别退。

## 9. 不变量总表

1. 事件流只追加；投影可重建（`scripts/rebuild-card.mjs` 即证明）。
2. 任何新功能都要有开关，关掉回到 3.0 行为。
3. 写侧（自写、修订、纠正确认）都要能回答「谁写的、什么时候、依据哪句话」。
4. 检索与召回只读；不因一次查询改变任何事实。
5. 时间一律以「那句话被说出的那一轮」为准（`saidAt`），不是写库时间。
6. 图片、原文、事实三层各自独立：图片按 sha1，原文在窗口账本，事实在长期库；任何一层缺失只降级，不报错中断。
