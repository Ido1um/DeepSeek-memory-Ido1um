## 0. 一句话结论

上一版只做了“忘记多少分”（R 衰减）和“忘得模糊时怎么说”（模糊投影）；这一版补上 **忘记的是什么**：
**意义 S、细节 D、可检索 R、情绪残留 E、巩固 C、干扰 I 六个量分开算**，再补 **碎片化表示、重构可信度、线索触发** 三件事。
结论仍然是：不换架构、不引向量、不让模型生成记忆。

## 1. 六变量对齐（本方案的定义）

| 识海变量 | 本方案字段 | 定义与取值 | 现状 |
|---|---|---|---|
| S 意义强度 | `I`（现有） + `I_eff` | `I` 写入时定（0.2–1）；`I_eff = I · 0.5^(年龄/365d)`，hard/rule/persona/identity 不衰减 | 已有 `I`；`I_eff` 新增，跨度 < 半年时几乎无影响 |
| D 细节完整度 | `D`（新） | 0–1，写入时 1；按类半衰期衰减，受 E/C/I 调制 | 无 |
| R 可检索性 | `R`（现有） | `R = 0.5^(未提及天数/S_eff)`，已有 | 已有，本轮把 S_eff 接入 C |
| E 情绪残留 | `emo` + `E_t`（新） | `emo` 写入时定（−1..1）；`E_t = emo · 0.5^(天数/E_half)`；只用于排序/语气，不进事实 | 修订 1 只有 `emo`，无时间衰减 |
| C 巩固程度 | `str`（修订 1 的 P1） | 0.2–2，默认 1；只有用户明说/确认才涨 | 规划中 |
| I 干扰程度 | `interference(topic)`（新） | 同 topic 的活跃事实数（不含自己）；读时计算，不落库 | 无 |

衰减关系按来源：`λ_S < λ_D`（意义比细节慢），`λ_E` 更小（情绪更久）。落到半衰期就是：
`D_half`（天）：event 30、note 30、pref 90、long/general 90、hard/rule/persona/identity = ∞；
`S_half`（意义）：统一 365，身份类 ∞；
`E_half`（情绪）：普通 180，`|emo| ≥ 0.7` 时 365。

**分级调制**（来源里 λ 受 E/C/I 影响，这里给可实现的乘子）：

```
D_half_eff = D_half_base × (1 + 0.6·(C−1)) × (1 + 0.4·|E_t|) / (1 + 0.3·min(I,3))
S_eff      = S_class × (0.6 + 0.4·C)          # 即修订 1 的双强度
R          = 0.5^(未提及天数 / S_eff)
```

所有乘子有上下限（C∈[0.2,2]、|E|≤1、I≤3），保证不会出现“永不衰减”或“一天忘光”。

## 2. 设计原则（在修订 1 的四条上再加两条）

1. 准确可审计：进 prompt 的每个字必须能追到 `quote/src/fragments`；不改写原文。
2. 无自强化：检索不涨 I/S/C/D；只有用户再说一遍才算巩固。
3. 硬预算：注入 ≤2500 字，`hard` 永不裁。
4. 事件流不物理删：作废/过期/降档都是事件。
5. **不生成、只拼装**：碎片拼接只用固定连接词，不调用模型补写；拼装要标可信度。
6. **置信度外显**：重构内容永远不说“我确定/100%”，按 Q 分档说“比较确定/大概记得/只记得片段”。

## 3. 机制设计

### 3.1 属性与片段（P0-a）

沿用修订 1 的 `emo / rel / scene`（扁平、可选、默认 0/0.5/''），并新增：

- `fragments: string[]`（≤3 条，每条 8–20 字）：写入时从 `value` 按标点切分、去停用词/代词、保留名词性片段，取前 3 条；不调模型。
- `D0`: 写入时 1.0；`D` 由读取时按上面的公式算出，**不落库**（避免每次写回）。
- 老数据缺 `fragments` 时，只在 `D<0.6` 且 class∈{event,note} 的读取场景即时从 `quote/value` 派生（不写库、不改分数）。

事件示例：

```json
{"ev":"fact","id":"h-...","about":"user","sig":"user:生日","topic":"user:birthday",
 "class":"identity","tier":"hard","I":0.8,"value":"……","quote":"……",
 "emo":0.7,"rel":1,"scene":"home",
 "fragments":["11 月 2 日","答应了饭管够","五碗"],"at":1793361261071}
```

**边界**：`fragments` 只服务“细节掉光时怎么说话”，不参与真值判断；hard 类写碎片也只做展示备份。

### 3.2 激活值（P0-b，修订 1 的扩展）

```
A = 100·I_eff·R
  + match            # topic 12 / sig 8 / 关键词 5
  + 6·E_t·rel        # 情绪残留 × 关系
  + 4·exp(−daysSinceHit/7)
  + cue              # 线索命中，≤15
  − 3·min(I_sim,3)   # 相似记忆干扰
```

- hard 档：`base = max(base, 80)`；`salienceFloor = 20`，低于阈值不注入、`recall` 仍可查；
- `cue` 由当前消息算：人物 6、场景 6、时段 4、情绪 4，封顶 15（实现：`src/v10.mjs` 的 `cueHits`）；
- 权重集中在 `v10.json` 的 `weights`（默认 topic 12 / sig 8 / kw 5 / affect 6 / recency 4），`recall --explain` 逐项打印；
- 干扰项只在 `I_sim>0` 时扣，最多 −9，避免把正常排序压乱。

### 3.3 细节模糊与重构（P0-c，替换修订 1 的 3.3）

**先算 D，再决定说多细；R 只管“能不能被想起”，不管“记得多清”。**

| class / D | 展示形态 |
|---|---|
| hard / rule / persona / identity | 永远原文（D 视为 1），不模糊、不加可信度标签 |
| 其他，`D ≥ 0.6` | 原文；正常陈述（Q 高档不加前缀） |
| 其他，`0.3 ≤ D < 0.6` | `「标签：首句」（细节记不全了）`——细节掉了一半，先说大概 |
| 其他，`D < 0.3` 且有 fragments | `「标签：片段1、片段2……」`；只拼原文子串，用「、」连接，不生成新词 |
| 其他，`D < 0.3` 且无 fragments | `「标签：topic 中文标签（细节已经模糊）」`，不展开 |

**重构可信度**（只影响措辞，不影响入库）：

```
Q = (0.4·hasQuote + 0.2·hasSrc + 0.2·userConfirmed + 0.2·crossFact)
    / (1 + 0.15·joints)
```

`joints` = 本次展示里把碎片拼成句子所用的连接数（模板固定，通常 1–2）；`userConfirmed` 取该 fact 是否有 manual/update 事件；`crossFact` 取同 topic 是否有第二条佐证。
分档：`Q ≥ 0.7` → 高；`0.4–0.7` → 中；`< 0.4` → 低。**卡（事实卡）永不进入这套措辞。**

措辞做成可配置的三档 `qLabels`（`v10.json` 里覆盖，默认 比较确定 / 大概记得 / 只记得片段）：

| 档 | 默认 | 说明 |
| --- | --- | --- |
| 高 | 比较确定 | 有原文或来源，直接陈述 |
| 中 | 大概记得 | 细节不完整，说首句并标「细节记不全了」 |
| 低 | 只记得片段 | 只拼 8–20 字原文碎片 |

渲染规则：**先说多细由 `D` 决定，说话底气由 `Q` 决定**——高档不加前缀（直接陈述，避免每句话都带“我记得”显得出戏）；中/低档加「标签：」前缀；低档只拼 8–20 字原文片段，用「、」连接，拼不出来就退回 topic 标签 +「细节已经模糊」。措辞可以按角色的口吻改，不影响判定逻辑。

### 3.4 `retrieved` 事件（P0-d，沿用修订 1）

记录“被想起过”：只加 `accessCount` 与 `lastRetrievedAt`，不动 I/S/C/D/R；同 fact 每天最多 1 条；多带一个 `cue` 字段便于回看“为什么想起”。用途：星图呼吸、沉睡统计、未来“用户复述才加分”的闭环数据。

### 3.5 巩固 C 与双强度（P1，沿用）

`str`（即 C）默认 1，明说/确认 +0.2（上限 2），被纠正 −0.4（下限 0.2）；驱动 `S_eff` 与 `D_half_eff`，并把 `D` 的衰减与“最近被确认”松耦合。**检索命中不涨 C**。

### 3.6 干扰 I（P1，新）

同 `topic` 的活跃事实 ≥2 时：`I_sim = 数量−1`；
- 排序扣 `3·min(I_sim,3)`；
- 细节半衰期除以 `(1 + 0.3·min(I_sim,3))`，让“同主题说法一多，细节老得更快”；
- 有冲突时先走 `supersede/conflict`（v8 已有），干扰只影响展示层，不影响真值。

### 3.7 线索触发 / 触景生情（P1，新）

线索从当前消息与会话上下文取：人物（`rel` 主语）、场景（`scene` 词）、时段（夜/日）、情绪（情绪词）。
- `cue` 最多 +15，作用是把“平时 12–15 分、低于阈值”的记忆抬到 20 以上 → 触发注入；
- **只对 `R ≥ 0.15` 的条目生效**，防止把早已沉底且没意义的记忆硬拉上来；
- 每次触发写 `retrieved.cue`，工作台可看“最近因何被想起”。

示例：平时 `A=13` 的一条搬家记忆，在“夜里 + 提到搬家 + 情绪偏低”的对话里 `cue=15` → `A=28` → 进入检索段，但 D 只剩 0.25，于是只说碎片。

### 3.8 情绪残留 → 语气提示（P2，默认关）

`E_t` 不写进事实卡。只在检索段追加一行（≤40 字）：
「上次谈到 {topic} 时气氛偏低，注意语气」——依据是 `|E_t|≥0.6 且 D<0.4`。
开关 `memory.v10.toneResidue`，默认 false；影子跑一周再开。

### 3.9 行为记忆与“被改变”（P2，默认关）

只在明确反馈时抽：「你上次说的那个办法有用」「别再那样了」→ 写 `class=event`、`I=0.4`、`source=behavior` 的 fact；不做隐式推断。
“被改变”不落成事实，而是聚合为 **人格语气摘要**（只读文档 `profile-tone.md`，由日终任务从高 E 事件生成，≤200 字，人工可改）——避免让模型把“我变了”编成记忆。

## 4. 兼容与开关

- 新字段 `fragments`、`D0` 可选；`D/E_t/I_sim` 都是读取时算，不写库；
- 新配置 `memory.v10 = { enabled, attrs, activation, cue, fuzzy, qRecon, dualStrength, interference, toneResidue }`，默认 `enabled=false`；
- `enabled=false` 时输出与今天**逐字节相同**（快照测试锁死）；`hard` 预算、卡投影、轮转、日终、提醒都不动；
- 老事件无 `fragments` 不报错；`materialize` 不迁移、不回填；
- 回滚：开关改 false + 重启桥接（10 秒）。

## 6. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 碎片拼装显得机械 | “记得你提过：A、B（只记得这些）”像机器人 | 模板只两种；`D≥0.3` 不出碎片；人工抽查 20 条 |
| 碎片误导 | 碎片脱离语境 | 每片必须来自原文子串；不加连接词以外的词；带时间 |
| 双重衰减 | S 与 R 都衰减导致掉太快 | `I_eff` 只在 >180 天时启用，先观察 |
| 情绪误判 | 排序偏 ±6 | 权重固定；hard 不抽 emo；explain 可查 |
| cue 误触发 | 什么都往上浮 | 只对 R≥0.15；cue ≤15；触发写日志可回归 |
| Q 公式拍脑袋 | 标签不准 | 先只分 3 档、不参与排序；一个月后按人工标注校准权重 |
| 干扰扣分过度 | 同主题记忆全被压 | 扣分上限 −9；只影响排序不影响真值 |
| 字段变死数据 | 加了没人读 | 每个字段必须有读取点（排序/展示/统计） |

## 7. 验收指标

1. `recall --explain` 100% 有分解，且 `cue`/干扰项可单独看到；
2. 注入 ≤2500 字、`hard` 保留 100%（沿用 `scripts/budget-compare.mjs`）；
3. 已知误召回回归：「我妈生日」与「我生日」永远是两条 sig；
4. “触景生情”用例：构造 `A=13` 的旧记忆，在场景+人物+时段命中时 `A≥20` 且被注入；
5. 碎片抽查 20 条：每个碎片都是原文子串，无编造；
6. Q 标签抽查：`Q<0.4` 的展示不得出现“确定/100%”字样；
7. `retrieved` 每天每事实 ≤1 条；`recall` p95 < 50ms（5000 条压测）。

## 8. 明确不做

- 不用 LLM 生成细节、不做“脑补”；
- 不做 embedding / 向量库；
- 不让 `E`（情绪）进事实卡；
- 不把 `D` 落库（读时算，避免写放大）；
- 不做隐式行为推断；
- 不一次上齐六变量（先 S/D/R/E/C，I 最后）；
- 不改硬预算、硬事实、轮转、日终。

## 9. 与 LTM、与修订 1 的关系

- 修订 1 的四个增量（属性、激活竞争、模糊投影、`retrieved`）全部保留，只是“模糊”的判据从 `R` 换成 `D`，并补了碎片与 Q；
- LTM 年度记忆可直接复用 `fragments/D/E_t/I_sim` 作为长周期元数据；顺序仍是 v10 → LTM；
- 本方案不新增存储文件，全部字段进 `state/longterm.jsonl` 的事件里，卡与备份机制不变。

---

## 10. 需要拍板的三处

1. `D_half` 的基准值（event/note 30 天、pref/long 90 天）是否合理；
2. `cue` 上限 15 与 `salienceFloor` 20 的组合，会不会让旧记忆太容易被“触景生情”；
3. Q 的三档措辞（「比较确定／大概记得／只记得片段」）是否符合你的角色口吻（`qLabels` 可配）。

这三处是仅有的经验值，其余都是确定性规则。

## 附：来源概念 → 本方案映射

- 六变量 → `I/I_eff`（S）、`D`、`R`、`emo/E_t`（E）、`str`（C）、`I_sim`（I）
- 细节衰减 `D(t)=D0·e^(−λD·t)` → `D = 0.5^(天数/D_half_eff)`（等价，λD = ln2/D_half）
- `λS < λD` → `I_eff` 半衰期 365 天 > `D_half` 30–90 天
- 情绪残留更久 → `E_half` 180/365 天，且只用于排序与语气
- 记忆碎片化 → `fragments` + 分档渲染
- 重构与可信度 → `Q = Σevidence / (1 + joints)`，三档措辞
- 线索触发 → `cue` 加到激活值，只对 R≥0.15 生效
- “忘记经历不等于抹掉改变” → P2 的 `profile-tone.md` 语气摘要，而不是伪造记忆
